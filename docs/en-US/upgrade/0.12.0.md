# Upgrade to 0.12.0

This version adds unified single/multiselection styling, up to three AVWAP bands, FRVP display options, and curve/doubleCurve/arc. The catalog grows from 53 to 56; KLineCharts stays at 10.1.0. Datafeed, HistoryResult and HTTP signatures remain unchanged. Local candidate artifacts do not imply npm publication.

## Compatibility and integration

ChartLayoutV4, WorkspaceDocument v2, shared documents v1 and preferences v1 remain valid. Missing AVWAP band fields mean none. Missing FRVP display fields retain left placement, 30% width and previous level styling. New definitions use existing anchors/styles/parameters. Unknown tools/algorithms and invalid parameters fail while preserving stored originals; never discard unknown definitions and overwrite the document.

Custom descriptors may declare actual `styleControls` for stroke, fill, width/style, text color and font size. Omission retains legacy common styles; an empty array disables quick styles. Templates consume the standard style keys. Cross-tool templates explicitly apply common styles only, preserving text, coordinates and parameters. Color parameters accept #RRGGBB/#RRGGBBAA or transparent.

Register third-party templates through the peer engine's `registerOverlay` before constructing charts with matching stable namespaced names and catalog entries. Missing templates fail before DOM construction; chart disposal does not unregister them. See the [native JS/TS example](https://github.com/evotrader/TradingChest/tree/main/examples/drawing-workbench).

## Mathematics and interaction

AVWAP preserves its original source and center. Bands use the source-price volume-weighted population deviation or absolute-center percentages, with up to three multipliers. Unrepresentable bands retain the center and an explicit reason rather than fabricated zero width or clamped prices. FRVP placement, width, level styles and extension do not change bins or the included range.

Curves are defined in projected screen coordinates, while persistence stores anchors. Curve clicks start/end/control; doubleCurve adds a second control; arc's third point lies on the arc. Degenerate geometry retains definitions and controls. Rendering and hit testing use the same bounded segments. See [formulas and parameters](../drawings.md#drawing-refinement), [curves](../drawings.md#curves) and [remaining differences](../drawings-coverage.md).

Batch operations retain per-object confirmations, one transaction per undo/redo, pending/rejection/unknown semantics and sharing permissions. Internal presentation coalescing does not change public notification order. Object management, wide/narrow layouts, keyboard editing and native IndexedDB saving use the same command path.
