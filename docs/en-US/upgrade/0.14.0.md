# 0.14.0: attached text and dense editing

This page describes the locally validated 0.14 candidate contract. It has not been published to npm. The stable install command remains `npm install trading-chest@0.12.0 klinecharts@10.1.0`; consume local 0.14 through its actual tarball. The KLineCharts peer stays at 10.1.0 and the catalog remains 56 tools.

## Attached text

Seven existing tools gain optional bodies:

| Tool ID | `textMode` | `labelGeometry` |
| --- | --- | --- |
| `horizontalStraightLine` | `attached` | `line` |
| `straightLine` | `attached` | `line` |
| `segment` | `attached` | `line` |
| `rayLine` | `attached` | `line` |
| `parallelStraightLine` | `attached` | `line` |
| `priceChannelLine` | `attached` | `line` |
| `rect` | `attached` | `box` |

`textAnnotation`, `callout`, `note` and `anchoredText` declare `textMode:'body'` and retain their original creation flow. Other built-ins gain no attached bodies; existing measurement/position labels are not drawn twice.

Select an object and use Add / edit text in its context menu, double-click editing or the Drawing manager text settings. Attached tools do not automatically prompt after drawing. On first body input, the UI confirms text and `labelVisible:true` together. Direct APIs retain `update.patch.text`, which never implicitly shows text; visibility is explicit:

```ts
const result = await chart.executeDrawingCommand({
  type: 'update', ids: ['drawing-id'],
  patch: {
    text: 'Area of interest\nAwait confirmation',
    parameters: { labelVisible: true, labelAlign: 'center', labelPosition: 'above' },
  },
})
if (result.status !== 'completed') console.error(result.message, result.items)
```

Defaults are `labelVisible:false`, `labelAlign:'center'` and `labelPosition:'above'`. Alignment accepts left/center/right; position above/on/below. Empty bodies draw no label. The sole body is the `overlay.extendData` string or a plain object's `text` field, preserving other JSON metadata. Arrays or other primitive content cannot be forcibly converted to objects. Color/family/size use `overlay.styles.text`.

Lines use the complete visible path of the first valid reference line in original figure order; boxes use actual rectangle bounds. Above/below has an 8 CSS px gap. Text reprojects with the pane, axes and zoom. Multiline drawing and hits share geometry, and long text clips without rewriting its body. There are no persisted label coordinates or enlarged auto price ranges. Cancellation, IME, Ctrl/Cmd+Enter, Escape, rejected/unknown confirmations retain the original editing path. Unconfirmed drafts are not confirmed content.

## Overlap selection

Right-click or touch-and-hold at a hit, then open Select objects here (N). Confirmed, visible, period-eligible objects with current projections in that pane follow native zLevel from high to low, retaining original event routing order for ties. Names, tools, scopes and opaque logical IDs distinguish candidates. Host-managed disabled entries explain why; locked objects retain the existing select policy.

All stable candidate IDs remain available; only visible rows and overscan mount, at most 60 rows. ArrowUp/Down and Home/End reach the full list, Enter invokes the original select command, and Escape closes while preserving the previous selection. Closing restores focus. Open lists recheck hiding, deletion, ordering and scope changes; binding/context switches cancel them. Selection, location and cancellation do not write drawing content or backend annotations.

## Translation with explicit units

Select objects in Drawing manager, open Precise translation, enter signed bars or price displacement and select Price value or Tick. Existing dragging and `move(dx,dy)` remain pixel operations. The new programmatic entry is:

```ts
const result = await chart.executeDrawingCommand({
  type: 'translate', ids: ['drawing-id'],
  bars: -2, price: { unit: 'tick', amount: 3 },
})
if (result.status !== 'completed') console.error(result.message, result.items)
```

Bars and tick counts must be safe integers; price values finite. Supply at least one displacement: blank is not zero. All-zero requests submit no content/history. Tick requires an explicit finite positive current `SymbolInfo.tickSize`, without inference from precision, ticker or market. Decimal multiplication/addition uses an independent 50-digit configuration in the original value domain followed by one Number conversion, without changing host settings or rounding to display precision.

| Built-in tools | Bars | Price/tick |
| --- | --- | --- |
| `anchoredText` | Unsupported | Unsupported |
| `anchoredVwap`, `fixedRangeVolumeProfile`, `regressionTrend`, `regressionChannel` | Supported | Unsupported; nonzero requests reject the whole batch with zero writes/new history |
| Remaining 51 tools | Supported | Supported |

Each instance also needs currently resolvable market anchors in one writable document/scope, pane and effective price axis. Logical/viewport anchors retain existing move controls. Targets cannot be split or discarded to bypass checks.

Nonzero bars move through actual confirmed loaded indices and preserve fractional positions between neighbouring bars. Lunch breaks, weekends and sparse bars are not elapsed-time arithmetic. Out-of-range targets, unresolved sources or missing interpolation neighbours reject whole-batch preflight without fabricated future timestamps. Price-only moves preserve the complete original time anchors. Nonfinite derived values, nonpositive log values and invalid geometry reject.

The batch shares one confirmed market/axis context and follows existing enqueue, whole-batch preflight, per-object write guards, serial confirmation and history. Changes to document, binding or confirmed time structure after queuing/yielding cancel old operations; normal same-bar updates and tail appends do not constitute structure invalidation. Partial confirmation retains confirmed prefixes and explicitly reports unattempted suffixes. Backend uncertain writes are not automatically retried. Check `status` and every `items` result. A successful batch creates one undo/redo transaction.

## Third-party capabilities and templates

Continue calling the peer's `registerOverlay` before supplying a `DrawingToolDescriptor` through `drawingCatalog`. New fields are `textMode?:'body'|'attached'`, `labelGeometry?:'line'|'box'` and `numericMove?:{bars:boolean;price:boolean}`. Attached requires labelGeometry and corresponding standard line, rect or rectangular polygon figures. The same text parameters, editing, saving and projection paths apply. Body tools retain `mode:'text'` creation.

Numeric capabilities require explicit declaration. Omitting `numericMove` means false for both, without inference from category, name or registered template. Declaring true still requires valid anchors, axes, ownership and current permissions. Descriptors remain copyable declarations without new function registration or host-specific interfaces.

Templates, defaults and recent styles retain only styles and parameters. Same-tool presets may retain `labelVisible/labelAlign/labelPosition`, excluding bodies, anchors, logical/backend IDs and scopes. Copying/pasting drawing objects preserves bodies with new IDs. Full same-tool templates and explicit cross-tool common styles retain their existing boundaries.

## Documents and alerts

ChartLayoutV4, WorkspaceDocument v2, shared v1 and preferences v1 stay unchanged. Bodies and parameters use existing fields. Missing fields in 0.13 documents retain the old appearance without automatically adding labels; reads do not rewrite originals. Older versions reject unknown new parameters through existing validation and preserve originals, without silently discarding new content on rollback.

Attached-body, visibility, style and position edits do not change anchors or reset drawing-alert comparisons. Geometry moves retain existing source-change handling. Backend authority, partial confirmation, uncertain results, shared CAS and one-operation/one-undo remain. Datafeed and host APIs add no account, currency inference, quantity, order or background-monitoring behavior.

## Performance and validation status

Optimization targets repeated JSON checks/workspace copies within one restore and lazily derived confirmed-market analysis indices. Independent reads retain full structure/content validation. Public callbacks, per-object confirmations, history and resource disposal keep their contracts.

Local functional, three-browser, installed-package/framework and real-backend acceptance passed. Rechecking the retained complete original samples against ten operator-approved budget changes yields 166/166; the other 156 limits remain unchanged, with failures and slow samples preserved. Under the fixed sampling conditions, restoring 1002 objects with 50k bars took at most 747.3ms versus the 898.5ms baseline, an improvement of about 16.8% that meets the original 808.65ms target. The longest complete task was 192ms against the approved 200ms ceiling; a 10% improvement is no longer claimed for that metric. Both 100-cycle cleanup workloads passed. Performance tests use isolated synthetic market data; real-backend workflows were validated separately. These local results do not imply npm publication or identical timings on other devices.
