# Upgrade from 0.6.0 to 0.7.0

KLineChart stays pinned to 10.1.0. Streaming, comparison, replay, confirmed drawings and v3/workspace storage retain their contracts. Generic analysis APIs do not take ownership of business calculations or data services.

1. Install trading-chest 0.7.0 with klinecharts 10.1.0 and retain the CSS import. Prefer trading-chest/chart for charts; React/Solid keep existing entrypoints.
2. indicatorCatalog is optional; omission retains all built-ins. An explicit catalog must contain indicators used by initialization and layouts. Register namespaced external templates before construction. Instance APIs return real IDs; settings/removal address IDs instead of assuming unique names. Defaults follow templates (MA four, RSI three); legal variable-length layouts are not padded.
3. Obtain getAnalysisContext after onDataReady and add layers using that token. Symbol/period/confirmed-basis changes invalidate handles; dispose and resend. Same-basis continuation retains scope. Hosts keep HTTP/WS, cancellation, result ordering and ownership.
4. Timestamp series explicitly declare placement/valueType. Main price requires matching known dataBasis. Date-only results use label-series with raw values, without guessing trading times or currencies. Replay availability applies to canvas/list/clicks/tooltips; labels without precise availability are hidden.
5. Analysis data and visibility are not persisted and require no database migration. Layout v3 excludes runtime indicator/pane/axis by real IDs; hosts resend analysis snapshots. Existing drawings and backend annotation references remain; never delete user data to restore.
6. ChartWorkspace height now defaults to 100%. Give the parent a definite height, or explicitly pass a number when preserving an old fixed-height host. locale/theme/toolbar own workspace chrome while per-cell layout restore retains its existing meaning.

`npm run test:browser` starts package-local Vite on a free port, resolves local @playwright/test and archives traces/JSON. Missing browser/test dependencies fail; run `npx playwright install chromium`. See [getting started](../getting-started) for the standalone tarball example.

Performance keeps original effective limits: ordinary 10k single cold 265.60000002384186ms; 50k single and 10k/50k plus three comparisons cold 500ms. Update/interaction/multi-chart budgets are unchanged. tests/browser/performance-budgets.json retains full precision and provenance. Legacy baselines are compatible provenance inputs and never repeatedly expand limits. Analysis benchmarks first enforce original control budgets and then compare same-environment increments. One hundred disposal cycles check owned resources; GC heap trends are recorded when available, without claiming universal permanent zero leaks.

`npm run test:performance` starts its own server and runs original single/comparison/workspace plus paired analysis workloads. Timing samples disable tracing so instrumentation does not change budget measurements.

On 2026-10-17 the operator approved only the new analysis dual-chart cold ceilings: 350ms for 10k bars per chart and 750ms for 50k bars per chart. The other 46 performance gates retain their original limits, including controls, single-chart analysis, updates and interactions. These two gates replace the paired cold increment formula. analysisColdOverrides records their scope and provenance; output retains both the original incremental limit and the approval.

When only budgets change and product code and measurement conditions are unchanged, run `node tests/browser/performance.mjs --recheck-analysis <original-complete-analysis-samples.json> <new-result.json>`. The script verifies complete sampling across all four cases, recorded statistics and disposal results, then reuses the sampling gate logic. It neither starts a browser nor overwrites the original evidence; a recheck is not a new measurement.
