# Upgrade to 0.8.0

0.8.0 replaces the 0.7.0 history interface and adds asynchronous named workspaces. KLineChart remains pinned to **10.1.0**; React/Solid/ESM/CJS/UMD entries remain. This guide describes the source contract; local tarball validation does not imply npm publication.

## Migrate Datafeed

1. Replace `getHistoryKLineData(symbol,period,from,to,context?)` with `getHistoryKLineData(symbol,period,query,context?)` in implementations, comparison providers, doubles and callers.
2. Handle query.kind before/range. Timestamps are Unix milliseconds. before excludes its upper bound; countBack targets a bar count, not calendar periods. range reads the complete `[from,to)` interval.
3. Always return `{bars,basis?,metadata?,hasMoreBefore?}`, never bare arrays. Before requires boolean hasMoreBefore. Only confirmed provider evidence establishes exhaustion. Short pages/empty windows do not imply false; empty plus true is rejected. Unfinished searches report retryable errors instead of invented empty data.
4. Range may omit hasMoreBefore; partial ranges cannot confirm complete reload/adjustment/recovery. Basis and optional metadata belong to this exact response, never global last-request state.
5. Propagate signal to real requests. Date-window adapters share cancellation/timeout and bound their search to 24 interval requests. Without committable data or a confirmed boundary, report HISTORY_BOUNDARY_UNRESOLVED.

```typescript
async function getHistoryKLineData(symbol,period,query,context) {
  if (query.kind === 'before') {
    // The host adapter must establish the actual earlier-history boundary.
    return hostHistory.readBefore(symbol,period,query,context?.signal)
  }
  return hostHistory.readRange(symbol,period,query,context?.signal)
}
```

There is no runtime shim for positional arguments or array returns. DataSession.getHistory takes the same query; HistoryBatch retains SeriesIdentity. Comparison subscription snapshots use HistorySnapshot without required pagination boundaries.

## State and retry

Use onDataState.dataStatus for the complete confirmed dataset and lastRead for the committed read only. Metadata is optional. Undeclared provider observation times/delays remain unknown, never calculated from network completion or the latest bar. Optional subscribeStatus carries connection/revision/error notifications without another data stream. Providers without status capability remain unknown.

Show message, errorCode and operation, and call `chart.retryData()` to retry the failed request. Prepend retries preserve the original before anchor and existing graphics, then restore pagination after success. reloadData still reloads the complete interval. Revision notifications request reload rather than live price alerts. Existing confirmation/rollback obligations remain through failure, cancellation, identity change and disposal.

DefaultDatafeed still uses Polygon with valid credentials. The documented 2003-09-10 stock coverage floor applies only to market='stocks', never other markets. Streaming remains stocks/1m/adjusted:false. No provider or calendar is added.

## Migrate workspaces

Replace ChartWorkspaceOptions storage/storageKey with `store:WorkspaceStore`. Use `createIndexedDBWorkspaceStore({databaseName?})` or inject a real asynchronous service. Scope is the original context; IDs/revisions are opaque. Same-ID update/delete must atomically compare expectedRevision in storage; read-then-unconditional-write is not CAS. Without a store, management is disabled. No default remote service or silent memory/localStorage fallback is supplied.

Methods are listSaved, saveAs, save, load(id), renameSaved, deleteSaved and importLegacy. A selector displays names. Trimmed names contain 1–80 characters and may repeat; IDs determine identity. Saving is explicitly manual; save edits before switching. renameSaved retains the stored document instead of saving current edits. Loading replaces/selects only after all cells succeed; failures keep the old view.

Revision conflicts report WORKSPACE_CONFLICT; refresh/reselect or save as another record. Missing/unavailable/corrupt data reports WORKSPACE_NOT_FOUND, WORKSPACE_STORE_UNAVAILABLE or WORKSPACE_INVALID_DOCUMENT. Cancellation/timeouts cannot prove a write did not occur. Resolve unknown outcomes by reading the same scope/ID before new storage mutations. Dispose the workspace before its owned store; borrowers must not close shared stores.

## Import legacy layouts

There is no automatic startup migration. Explicit `workspace.importLegacy(name)` reads the old `trading-chest-workspace-v1-${context}` or supported single-chart legacy keys through loadLayoutV3 and creates an optional record. Select/load the new ID afterward. Import does not replace the current view or delete/overwrite original keys. Corrupt data, missing symbols/periods and restore failures retain originals/current graphics.

WorkspaceDocument v1 and ChartLayoutV3 **retain their formats**. Names/IDs/revisions live outside the document. Market data, analytical layer data and runtime handles stay excluded; backend drawings remain references. Single-chart saveLayoutV3/listLayoutsV3 retain their original responsibilities.
