# Upgrade to 0.9.0

Version 0.9.0 focuses on independent integration: React chart/workspace components, DOM-free history validators, Next/Vue examples and a complete site artifact under `/TradingChest/`. KLineChart remains pinned to **10.1.0**. This page describes source contracts; a local tarball, build or docs site does not establish public npm/Pages publication.

## From 0.8.0

Existing chart/solid, ESM/CJS/UMD, CSS, history and layout formats remain. ChartLayoutV3, WorkspaceDocument v1 and named-workspace scope/ID/revision semantics are unchanged. Existing imperative integrations do not need to switch to React just to upgrade.

Import new `TradingChart`/`TradingWorkspace` **only from `trading-chest/react`**. The root retains LiveSharpeChart/DrawdownAreaChart and their types without adding the wrappers. ReactDOM is an optional peer; React consumers install a paired version. The matrix pairs 18.3.1/18.3.1 and 19.2.3/19.2.3. Pure chart/testing consumers need neither.

When migrating a React host:

1. Put construction settings in `initialOptions`. Use `createDatafeed(signal)` to create a separate feed every time. Never reuse a shared or disposed instance through StrictMode remounts.
2. Use dynamic theme/locale/timezone/styles/height props and `events` notifications. Initialization policies/identity are mount snapshots, replaced through a key; runtime operations keep the original ChartPro ref.
3. Distinguish instance `onReady` from actual-history `events.onDataReady`. Do not publish analytical snapshots or complete cell readiness early.
4. Replace per-cell roots with Context-preserving `renderCell` portals. Ready cells pass `{chart,captureOptions?}` with real local drawing IDs/backend annotation references.
5. Explicitly choose borrowed `store` or owned `createStore`, never both. Owned factories must return a disposable store. Borrowers must not close shared stores. Without storage, named management remains disabled.

Core history errors, pagination retry, replay recovery, staged layout replacement/old-view retention and unknown-write reconciliation remain authoritative. Wrappers do not own business APIs or introduce another data source.

## Server and testing entries

The React entry preserves `use client`. ESM/CJS support DOM-free imports and renderToString; the server renders an initial container and client effects create Canvas. Next.js 16.2.1 factories live in a Client Component, without consumer Solid aliases/transpilePackages. Root/chart/UMD do not promise SSR or server-side Canvas.

New `trading-chest/testing` reuses HistoryError, validateHistoryQuery, validateHistoryResult and public historical types without chart/Solid/React/DOM imports. Validation returns the original object without copying/freezing and cannot prove provenance or truthful exhaustion. Keep independent host expectations and real-source checks.

## Examples and docs

[Framework integration](../frameworks) covers React Vite, Next App Router, Vue Vite and datafeed-contract templates. Both analysis-sdk pages remain. Examples independently install a real tarball with explicitly isolated synthetic inputs, never production fallbacks. Vue uses the original chart lifecycle without a new Vue wrapper.

Docs use TradingChest branding/repository links while preserving upstream Apache license notices and attribution; the upstream CNAME is removed. `npm run docs:site` merges docs and static demos into `website/` at base `/TradingChest/`. Next requires a Node server and is linked as source/local-run instructions, not static SSR. The official Pages workflow uploads that artifact without DEPLOY_TOKEN. Public deployment is a separate maintainer publishing action.

See [API](../api), [data access](../data-access) and [getting started](../getting-started). Earlier consumers should first apply the existing [0.8.0](./0.8.0)/[0.7.0](./0.7.0) contract migrations.
