# 0.14.0：附着文字与密集编辑

本页描述已完成本地验收的 0.14 候选契约，尚未发布到 npm。稳定安装命令仍为 `npm install trading-chest@0.12.0 klinecharts@10.1.0`；本地 0.14 包须按实际 tarball 消费。KLineCharts peer 保持 10.1.0，目录仍有 56 项。

## 附着文字

七种既有工具增加可选正文：

| 工具 ID | `textMode` | `labelGeometry` |
| --- | --- | --- |
| `horizontalStraightLine` | `attached` | `line` |
| `straightLine` | `attached` | `line` |
| `segment` | `attached` | `line` |
| `rayLine` | `attached` | `line` |
| `parallelStraightLine` | `attached` | `line` |
| `priceChannelLine` | `attached` | `line` |
| `rect` | `attached` | `box` |

`textAnnotation`、`callout`、`note`、`anchoredText` 声明 `textMode:'body'`，保留原正文工具的创建方式。其它内置工具不增加附着正文，既有测量／多空头自动标签不重复绘制。

选中对象后从右键“添加／编辑文字”、双击或绘图管理的文字设置编辑；附着工具创建完成不自动弹框。UI 首次输入正文时将正文与 `labelVisible:true` 一起确认。直接 API 仍使用 `update.patch.text`，单改正文不隐式开启显示；显隐由参数显式控制：

```ts
const result = await chart.executeDrawingCommand({
  type: 'update', ids: ['drawing-id'],
  patch: {
    text: '关注区域\n等待确认',
    parameters: { labelVisible: true, labelAlign: 'center', labelPosition: 'above' },
  },
})
if (result.status !== 'completed') console.error(result.message, result.items)
```

缺省为 `labelVisible:false`、`labelAlign:'center'`、`labelPosition:'above'`；对齐选择 left/center/right，位置选择 above/on/below。空正文无标签。正文唯一存储为 `overlay.extendData` 字符串或普通对象的 `text`，其余 JSON 元数据完整保留；数组或其它原始内容不能被强制转成对象。颜色／字体／字号沿 `overlay.styles.text`。

line 以原 figure 顺序中第一条有效参考折线的完整可见路径定位，box 使用真实矩形边界；上／下间隔 8 CSS px。文字按当前 pane、轴、缩放重新投影，多行绘制和命中共用几何，长文字裁剪但不改正文，不保存独立标签坐标或扩大自动价格范围。取消、组合输入、Ctrl/Cmd＋Enter、Esc、确认拒绝／未知均沿原编辑链，未确认草稿不冒充真实内容。

## 重叠对象选择

命中处右键或触摸长按，打开“选择此处对象（N）”。当前 pane 的可见、周期允许、有当前投影的已确认对象按原生 zLevel 从高到低排列，同层沿原事件路由顺序。显示名称、工具、scope 与不透明 logicalId；宿主管理的禁用项给出原因，锁定对象沿原选择规则。

完整候选保留稳定 ID；只虚拟挂载可见行和 overscan，最多 60 行。ArrowUp/Down、Home/End 到达全部候选，Enter 调用原 select 命令，Esc 关闭并保留原选择，关闭后返回原焦点。打开期间重核隐藏、删除、排序及 scope 变化，绑定／上下文切换取消菜单。选择、定位或取消不写绘图内容和后端标注。

## 明确单位的精确平移

在绘图管理中选中对象，打开“精确平移”，填写有符号根数或价格位移并选择价格值／Tick。原拖动及 `move(dx,dy)` 仍是像素操作。程序入口新增：

```ts
const result = await chart.executeDrawingCommand({
  type: 'translate', ids: ['drawing-id'],
  bars: -2, price: { unit: 'tick', amount: 3 },
})
if (result.status !== 'completed') console.error(result.message, result.items)
```

根数和 tick 数量必须为安全整数，价格值有限；空输入不能当成零，至少提供一种位移。全零请求不提交内容或历史。Tick 需要当前 `SymbolInfo.tickSize` 明确为有限正数，不从价格精度、ticker 或市场推断。价格在原始值域用独立 50 位 Decimal 配置做十进制乘加，最后转换一次 Number，不影响宿主全局配置，也不按显示精度舍入。

| 内置工具 | 根数 | 价格／tick |
| --- | --- | --- |
| `anchoredText` | 不支持 | 不支持 |
| `anchoredVwap`、`fixedRangeVolumeProfile`、`regressionTrend`、`regressionChannel` | 支持 | 不支持；非零请求整批拒绝，零写入且无新增历史 |
| 其余 51 项 | 支持 | 支持 |

每个实例还须有当前可解析的 market 锚点，属于同一可写文档／scope、pane 和有效价格轴。logical／viewport 锚点仍用原移动操作；不能为通过检查自动拆批或丢弃对象。

非零根数按已确认、已加载真实 K 线索引移动，保留相邻 bar 间的分数位置。午休、周末及稀疏 bar 不按自然时长换算；目标越界、源无法解析或缺少插值相邻 bar 时整批预检拒绝，不制造未来 timestamp。仅价格位移完整保留原时间锚点。非有限派生值、log 非正及无效几何拒绝。

整批共享一次确认行情／轴上下文，沿原 enqueue、全批预检、逐对象写前 guard、串行确认和历史链。排队或让出后文档、绑定或确认时间结构改变会取消旧操作；正常同根更新及 tail 追加不作为结构失效。部分确认保留已确认前缀，未尝试后缀显式返回；backend 不自动重试 uncertain。必须检查 `status` 和各项 `items`。成功整批只形成一笔 undo/redo。

## 第三方能力与模板

继续先调用 peer 的 `registerOverlay`，再通过原 `drawingCatalog` 提供 `DrawingToolDescriptor`。新增字段为 `textMode?:'body'|'attached'`、`labelGeometry?:'line'|'box'`、`numericMove?:{bars:boolean;price:boolean}`。attached 必须指定 labelGeometry，并返回相应标准 line、rect 或矩形 polygon figure；库提供同样的文字参数、编辑、保存和投影入口。body 工具沿原 `mode:'text'` 创建正文。

数值能力必须明确声明，省略 `numericMove` 两项均为 false，不按类别、名称或已注册模板推断。声明 true 仍须通过锚点、轴、所有权及当前权限检查。目录只含可复制的声明，不新增函数注册项或宿主专属接口。

模板、默认和最近样式只保存 styles 与 parameters。`labelVisible/labelAlign/labelPosition` 可以随同工具预设保存，正文、锚点、逻辑／后端 ID 和 scope 均不复制。复制／粘贴绘图对象则保正文，并沿原规则生成新 ID。完整同工具模板和显式跨工具共同样式继续保持原边界。

## 文档兼容与提醒

ChartLayoutV4、WorkspaceDocument v2、shared v1、preferences v1 均不升版，正文和新参数使用现有字段。0.13 文档缺少新参数时保持原外观，不自动添加标签；读取不回写原件。旧版本遇到不认识的新参数会按原校验拒绝恢复并保原，不能承诺回退时静默丢弃新内容。

附着文字的正文、显隐、样式或位置不改 anchors，也不重置画线提醒比较点；移动图形仍按原来源几何变化处理。原后端 authority、部分确认、uncertain、共享 CAS 和一次操作一次撤销保持。`Datafeed` 与宿主业务接口不增加账户、币种推断、数量、下单或后台监控行为。

## 性能与验收状态

本次优化聚焦同次恢复中的重复 JSON 检查和工作台副本，以及按需派生确认行情分析索引；独立读取仍执行完整结构与内容校验。API 回调、逐对象确认、历史及资源释放契约不变。

本地功能、三浏览器、实际安装包／框架和真实后端流程均已通过。性能按操作者批准的 10 条预算调整，用保留的完整原样本复算为 166／166；其余 156 条门槛不变，未删除失败或慢样本。固定采样条件下，5 万根／1002 对象的恢复最大延迟为 747.3ms，比基线 898.5ms 改善约 16.8%，满足原 808.65ms 目标；完整最长任务为 192ms，采用批准的 200ms 上限，不再承诺该项也改善 10%。两组各 100 次清理通过。测试使用隔离合成行情，真实后端流程另行验证；这些本地结果不代表 npm 已发布，也不保证其它设备具有相同耗时。
