# 升级到 0.8.0

0.8.0 从 0.7.0 收敛历史数据接口并增加异步命名工作台。KLineChart peer 仍固定 **10.1.0**，React／Solid／ESM／CJS／UMD 入口不变。本页描述源码契约；本地 tarball 验证不等于已经 npm 发布。

## 迁移 Datafeed

1. 将 `getHistoryKLineData(symbol,period,from,to,context?)` 改为 `getHistoryKLineData(symbol,period,query,context?)`，所有实现、比较 provider、替身和调用方一起迁移。
2. 根据 `query.kind` 处理 before 或 range。时标是 Unix 毫秒；before 严格不含上界，countBack 为期望根数，不是自然周期；range 完整读取 `[from,to)`。
3. 统一返回 `{bars,basis?,metadata?,hasMoreBefore?}`，不返回裸数组。before 必须有 boolean hasMoreBefore；只有明确证据才可报告穷尽。空时间窗口或短页不能推导 false；空页加 true 被拒绝。查找未完成应报可重试错误，不伪造空数据。
4. range 可省略 hasMoreBefore；partial range 不确认完整重载／复权／恢复。basis 和可选 metadata 必须属于这次响应，不读取全局最新状态。
5. 把 signal 传到真实请求。按日期 API 查找最近根数时共享取消／超时，最多 24 次区间请求；无可提交数据且无法确认边界时抛 `HISTORY_BOUNDARY_UNRESOLVED`。

```typescript
async function getHistoryKLineData(symbol,period,query,context) {
  if (query.kind === 'before') {
    // The host adapter must establish the actual earlier-history boundary.
    return hostHistory.readBefore(symbol,period,query,context?.signal)
  }
  return hostHistory.readRange(symbol,period,query,context?.signal)
}
```

没有旧位置参数或数组返回的 runtime shim。DataSession.getHistory 接同一个 query，HistoryBatch 保留 SeriesIdentity。比较订阅快照使用 HistorySnapshot，无需携带分页边界。

## 呈现状态与重试

使用 onDataState 的 dataStatus 显示整个已确认数据集，lastRead 只解释本次成功提交读取。metadata 可选；来源观察时刻／声明延迟未提供时显示未知，不能用网络完成或末根时标代算。subscribeStatus 为可选连接／修订／错误通知，不包含另一份行情；无能力时 connection 为 unknown。

错误展示 message、errorCode 和 operation，并调用 `chart.retryData()` 重试原失败请求。分页失败保持原 before 锚点和已有图形，成功后继续分页；reloadData 继续负责完整区间重载。修订通知提示需要重载，不触发实时价格报警。失败、取消、切换和销毁保留原有确认／回滚语义。

DefaultDatafeed 仍用 Polygon 协议与有效凭证，股票文档覆盖下界 2003-09-10 仅用于 market='stocks'，不扩展到其他 markets。实时仍仅支持 stocks／1m／adjusted:false，不新增供应商或日历。

## 迁移工作台

将 ChartWorkspaceOptions 的 storage/storageKey 替换为 `store:WorkspaceStore`。可使用 `createIndexedDBWorkspaceStore({databaseName?})`，也可注入真实异步服务。scope 使用原 context；ID 和 revision 不透明；同 ID 更新和删除必须在存储中原子比较 expectedRevision，不能用先读再普通覆盖冒充 CAS。未注入 store 时管理禁用，不默认连接远端，也不静默回落内存或 localStorage。

新增 listSaved、saveAs、save、load(id)、renameSaved、deleteSaved 和 importLegacy。工作台通过选择器展示名称；名称 trim 后 1–80 字符，可重名，身份仍为 ID。保存为显式手动操作，切换前先保存未保存改动。renameSaved 保留已存文档，不把当前未保存视图顺便写入。加载全部窗格成功后才替换并选中，失败保留旧图。

更新／删除冲突抛 WORKSPACE_CONFLICT，刷新并重新选择或另存。不存在、不可用和损坏分别为 WORKSPACE_NOT_FOUND、WORKSPACE_STORE_UNAVAILABLE、WORKSPACE_INVALID_DOCUMENT。取消／超时不能证明写入没发生，界面以同 scope/ID 读取核对未知结果，核对前禁用后续存储变更。dispose workspace 后再 dispose 自有 store；借用者不关闭共享 store。

## 导入旧布局

启动时不自动迁移。检测并显式调用 `workspace.importLegacy(name)`，只读旧 `trading-chest-workspace-v1-${context}` 或 loadLayoutV3 支持的单图旧键，新增可选记录。导入成功后仍须选择／load 新 ID；当前工作台不被自动替换，旧键不删除或覆盖。损坏、缺标的／周期和恢复失败保留原件及当前视图。

WorkspaceDocument v1、单图 ChartLayoutV3 **不升级**；名称／ID／revision 在持久记录外层。行情、分析图层数据和运行时句柄不写入文档；后端绘图继续只保存引用。单图 saveLayoutV3/listLayoutsV3 API 保持原职责。
