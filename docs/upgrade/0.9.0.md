# 升级到 0.9.0

0.9.0 聚焦独立项目接入：React 图表／工作台、无 DOM 的历史校验、Next／Vue 接入示例，以及同一 `/TradingChest/` 站点产物。KLineChart 继续固定 **10.1.0**。本页描述源码契约；本地 tarball、构建或文档不表示新版 npm／Pages 已公开发布。

## 从 0.8.0 迁移

原 `trading-chest/chart`、`solid`、ESM／CJS／UMD、CSS 和历史／布局格式保留。ChartLayoutV3、WorkspaceDocument v1、命名工作台 scope／ID／revision 语义不变。已有 imperative 接入无需仅为版本升级改成 React。

新增 `TradingChart`／`TradingWorkspace` **仅从 `trading-chest/react` 导入**。根入口保留原 LiveSharpeChart／DrawdownAreaChart 及类型，没有新增两种包装器。ReactDOM 是 optional peer；使用 React 入口时安装配对 ReactDOM。验证组合是 18.3.1／18.3.1 与 19.2.3／19.2.3；纯 chart／testing 无需 React。

迁移 React 宿主时：

1. 将 imperative 图表构造字段放进 `initialOptions`，改以 `createDatafeed(signal)` 每次创建独立 feed。不要把共享单例或已经 disposed 的实例交给 StrictMode 下一次挂载。
2. theme／locale／timezone／styles／height 改用动态 props；通知放在 `events`。初始化策略与初始身份是挂载快照，变更用 React key；运行时操作继续用原 ChartPro ref。
3. 区分 `onReady` 的实例创建和 `events.onDataReady` 的真实历史确认。不要提前发布分析快照或完成工作台绑定。
4. 工作台以 `renderCell` portal 保留 Context，移除每 cell 自建 root。子图就绪传 `{chart,captureOptions?}`，保留真实本地绘图 ID 和后端标注引用。
5. 显式选择借用 `store` 或自有 `createStore`，不能同时传。自有工厂必须返回带 dispose 的 store；借用者不得关闭共享 store。无存储仍禁用命名管理。

原历史读取错误、分页重试、回放恢复、布局暂存／失败保旧和未知写入核对继续由核心实现。包装器不接管业务 API 或更改行情权威。

## 服务端与测试入口

React 入口有 `use client`；ESM／CJS 支持无 DOM 的导入及 renderToString，服务端输出初始容器，客户端 effect 才创建 Canvas。Next.js 16.2.1 示例的函数工厂位于 Client Component，无需消费者 Solid alias／transpilePackages。根／chart／UMD 仍不承诺 SSR 或服务端 Canvas。

新 `trading-chest/testing` 直接复用原 HistoryError、validateHistoryQuery、validateHistoryResult 和历史公共类型，不导入图表／Solid／React／DOM。校验返回原对象，不冻结或复制，也不证明来源或穷尽真实。不要用它取代宿主独立预期与真实数据核验。

## 示例和文档

[框架接入](../frameworks)列出 React Vite、Next App Router、Vue Vite 与 datafeed-contract 模板；原 analysis-sdk 两页保留。示例独立安装实际 tarball，使用明确标识的隔离合成输入，不是生产 fallback。Vue 沿原 chart 生命周期接入，没有新增 Vue 包装器。

文档品牌／仓库指向 TradingChest，保留上游 Apache 许可和署名；删除上游 CNAME。`npm run docs:site` 合并文档和静态演示到 `website/`，部署 base 为 `/TradingChest/`。Next 需要 Node 服务，仅提供源码／本地运行说明，不假装静态 SSR。官方 Pages workflow 上传这份产物，不依赖 DEPLOY_TOKEN；公开上线是单独的维护者发布动作。
